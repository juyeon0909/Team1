# 보안 작업 정리 — 2026-06-14

eatsfridge.site 프로젝트의 보안 점검 및 조치 내역.
"무엇을 발견했고 / 무엇을 고쳤고 / 무엇이 남았는지"를 한눈에 보도록 정리한다.

대상: Spring Boot 백엔드(`Beats`) + React 프론트(`Feats`)

---

## 1. 시작 배경

외부 보안 스캔(SafeDomain) 결과 등급 **D / 65점**, 위험도 HIGH.
지적된 항목은 모두 코드 버그가 아니라 **응답 헤더 + DNS** 설정 누락이었다.

| 스캔 지적 | 종류 |
|-----------|------|
| HSTS 누락 | HTTP 헤더 |
| Content-Security-Policy 누락 | HTTP 헤더 |
| X-Content-Type-Options 누락 | HTTP 헤더 |
| X-Frame-Options 누락 | HTTP 헤더 |
| DNS CAA 누락 | DNS 레코드 |

이후 코드 전반을 추가로 점검해 실제 코드 취약점도 함께 찾아 수정했다.

## 2. 코드 점검에서 새로 발견한 취약점

| # | 심각도 | 내용 |
|---|--------|------|
| 1 | 🔴 CRITICAL | 비밀번호 재설정이 이메일 인증 통과 여부를 확인하지 않아, 이름+이메일만으로 임의 계정 비밀번호 변경(계정 탈취) 가능 |
| 2 | 🟠 HIGH | 패스워드리스 해지가 이메일만 받고 본인확인이 없어, 남의 2차 인증을 임의 해지·푸시 스팸 가능 |
| 3 | 🟡 MEDIUM | 로그인·인증번호에 브루트포스 방어(시도 제한) 없음 |
| 4 | 🟡 MEDIUM | 운영 환경에서 Security DEBUG·SQL trace 로깅이 켜져 민감정보 로그 유출 위험 |
| 5 | 🟡 MEDIUM | CORS에 와일드카드 `*`·원시 IP·미사용 출처가 섞여 과도하게 느슨함 |
| 6 | 🟡 MEDIUM | 이미지 업로드 시 형식 검증이 없어 svg/html 업로드로 저장형 XSS 가능 |

**양호했던 점:** SQL 인젝션 없음(전부 파라미터 바인딩), 비밀키 하드코딩·커밋 없음(전부 환경변수),
비밀번호 BCrypt 해시, 회원가입 권한 상승 차단(role 서버 강제), 관리자 API 권한 검사.

## 3. 오늘 실제로 수정한 것 (코드 반영 완료)

빌드·배포하면 적용되는 변경. 모두 `git`에 반영된 상태다.

### 🔴 CRITICAL 1 — 비밀번호 재설정 인증 강제
- 파일: `Beats/src/main/java/com/Plz/Beats/service/ResetPasswordService.java`
- 변경:
  - 인증번호 검증에 성공한 이메일에만 10분짜리 "인증 완료 증표" 발급(`verifiedEmails`)

  - 증표는 1회용(변경 즉시 폐기)
  - 인증번호 5회 오답 시 폐기(브루트포스 방어)

### 🟠 HIGH 2 — 패스워드리스 해지 본인확인
- 파일: `Beats/.../controller/PasswordlessController.java`,
  `Feats/src/pages/PasswordlessWithdrawalPage.tsx`
- 변경:
  - 백엔드: `email` 파라미터 제거 → 로그인 토큰(`Principal`)에서 본인 이메일을 꺼내 사용,
    비로그인 시 401
  - 프론트: 더 이상 보내지 않는 `email` 파라미터 제거(토큰은 자동 첨부됨)

### 🟡 MEDIUM 4 — 운영 로깅 차단
- 파일: `Beats/src/main/resources/application-prod.properties`
- 변경: prod에서 `org.springframework.security` 및 Hibernate SQL 로그 레벨을 INFO로 낮춤

### 🟡 MEDIUM 5 — CORS 정리
- 파일: `Beats/.../config/CorsConfig.java`, `Beats/.../controller/MemberController.java`
- 변경: 허용 출처를 실제 도메인만 남김(원시 IP·미사용 localhost·`*` 제거),
  메서드·헤더에서 `*` 제거, 컨트롤러의 중복 `@CrossOrigin` 제거

## 5. 아직 해야 할 일 (남은 작업)

코드가 아니라 **서버·DNS·배포**에서 직접 해야 하는 작업이다.

### (A) 빌드 확인 — 배포 전 필수
- 이 점검 환경에는 Maven/JDK21이 없어 자동 컴파일을 못 했다. 변경 파일은 수동 검토함.
- 로컬 또는 CI에서 한 번 빌드 확인:
  ```bash
  cd Beats && mvn clean package
  ```

### (B) 백엔드 재배포
- 위 백엔드 변경(재설정·패스워드리스·CORS·로깅·업로드)은 **재배포해야 반영**된다.
- master 브랜치에 push하면 기존 CI/CD(GitHub Actions → EC2 Docker)로 배포된다.

### (C) 프론트 재배포
- `PasswordlessWithdrawalPage.tsx` 변경 반영을 위해 프론트도 재빌드·배포(Frontend CD).

### (D) nginx 보안 헤더 적용  — `SECURITY_FIXES.md` 1단계
- EC2에서 nginx 설정에 `deploy/nginx-eatsfridge.conf`의 "보안 헤더 블록"을 추가
- `sudo nginx -t && sudo systemctl reload nginx`
- CSP는 처음엔 `Report-Only`로 켜서 화면 깨짐 없는지 확인 후 정식 적용 권장

### (E) CAA DNS 레코드 추가 — `SECURITY_FIXES.md` 2단계
- DNS 콘솔에서 ACM 기준 CAA 레코드 추가:
  ```
  eatsfridge.site.  IN  CAA  0 issue "amazon.com"
  eatsfridge.site.  IN  CAA  0 issuewild "amazon.com"
  ```

### (F) nginx 레이트리밋 활성화 (선택, 권장)
- `nginx-eatsfridge.conf`의 `limit_req_zone` / `limit_req` 주석을 해제

### (G) 적용 후 검증
```bash
curl -sI https://eatsfridge.site | grep -iE "strict-transport|content-security|x-frame|x-content-type|referrer"
dig CAA eatsfridge.site +short
```
- 온라인 확인: https://securityheaders.com/?q=eatsfridge.site

## 6. 검토만 하고 손대지 않은 항목(참고)

- **로그인 fail-open**: 패스워드리스 서버 장애 시 일반 로그인 허용(가용성↔보안 트레이드오프).
  정책 판단 필요해 그대로 둠.
- **JWT 무효화 불가**: 무상태 설계라 탈취 토큰 즉시 무효화 수단 없음. 만료시간 단축 또는
  Redis 블랙리스트 검토 권장.
- **인증 상태 메모리 저장**: 재설정 인증 상태가 서버 메모리에 있어 서버 증설·재시작 시 사라짐.
  운영 확장 시 Redis 등 공유 저장소로 이전 권장.
